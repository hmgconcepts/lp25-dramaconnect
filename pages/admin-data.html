🚑 Disaster Recovery Wizard — restore DramaConnect onto a completely FRESH database

Read this before you touch anything.

If the old project is merely paused, do not use this wizard. Go to supabase.com, restore the project, then press the 💓 heartbeat button on Platform Health. This wizard is for the case where the old project is genuinely gone — deleted, unrecoverable, or paused past the point of no return.

You will rebuild every production, member record, attendance history, casting decision, task, poll, event and announcement on a brand-new database. Member links are deferred rather than destroyed, and the re-link pass restores them automatically once people re-register.

  1. 1. Create the fresh project. At supabase.com create a new project (any region). Copy the new Project URL and anon / publishable key from Settings → API. Keep the old tab open; you will come back to it.
  2. 2. Install the schema. In the new project open SQL Editor → New query, paste the entire contents of database/complete-schema.sql, press Run, and wait for installed successfully ✅. The script is cumulative and safe to re-run, so a partial run is not fatal — just run it again.
  3. 3. Point the site at the new database. Edit assets/js/config.js and replace the URL and anon key with step 1's values. Push to GitHub; Vercel redeploys the very same site automatically.
  4. 4. Create your own account first. Open the site, choose Login → Request access and sign up. Then in Table Editor → profiles set your own row to role = 'super_admin' and status = 'approved'. You are now the owner of the rebuilt site.
  5. 5. Reconnect Google Drive. Go to the Drive tab here and paste your existing OAuth Client ID. OAuth credentials are scoped to your deployed URL, not to the database — the same Client ID works against the new project with no change at Google.
  6. 6. Run the recovery. Still on the Drive tab, press 📂 List backups, authorise, and on the newest backup click 🚑 Recover to new project. Alternatively use the Local tab above: select the archive file, choose Disaster recovery as the mode, type RESTORE and press restore. Either path verifies the SHA-256 seal before the first write, keeps every operational row, defers only the member links, and retries row-by-row so one bad row cannot sink the other 199.
  7. 7. Re-onboard people, then re-link. Broadcast the new address and approve everyone on Approvals. Then upload the re-link manifest you downloaded at the end of step 6 — every deferred attendance, casting, task, vote and RSVP link is rebuilt automatically by email, and you get an honest report of anything still unmatched.
  8. 8. Re-arm every safeguard. The heartbeat, the two GitHub secrets, UptimeRobot, Drive auto-sync and one fresh backup. Visit Platform Health and do not stop until every tile is green. A rebuilt site with no heartbeat will simply pause again.
